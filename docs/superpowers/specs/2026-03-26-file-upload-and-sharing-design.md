# 教学资源上传与空间分享体系设计说明

- 日期：2026-03-26
- 项目：教学资源管理系统
- 方案：B（资源中心 + 课程附件 + 独立空间文件库）

## 1. 目标

本次设计目标是在当前若依教学资源管理系统基础上，补齐“真实可用”的文件能力，使系统真正具备教学资源管理平台应有的上传、存储、预览、下载、课程附件管理、空间分享和权限配额控制能力。

本次改造必须满足以下要求：

1. 教学资源模块支持真实文件上传，而不是仅手工填写 URL。
2. 课程/章节支持课件和资料附件上传。
3. 空间管理支持文件夹、文件上传、分享、密码分享、有效期和下载限制。
4. 管理端支持对用户空间、上传大小、分享权限、账号状态做统一控制。
5. 存储层同时兼容本地磁盘与 MinIO，默认优先本地磁盘落地，后续可平滑切换 MinIO。
6. 最终补齐完整开发文档、部署文档、接口文档、一键脚本，并推送 GitHub。

---

## 2. 总体架构

本次文件体系采用“业务层 + 存储抽象层”结构。

### 2.1 业务层

业务层拆分为三类文件业务：

1. 资源中心文件
   - 用于教学资源上传
   - 包含资源主文件、封面图、文件元信息

2. 课程附件文件
   - 用于课程资料、章节附件、课件上传
   - 与课程、章节关联

3. 空间文件库
   - 用于教师/学生/管理员空间中的文件与文件夹管理
   - 支持分享与权限控制

### 2.2 存储抽象层

统一新增“文件存储服务接口”，底层提供两套实现：

1. LocalStorageService
   - 文件落本地目录
   - 适合当前项目先快速跑通

2. MinioStorageService
   - 文件存对象存储
   - 适合后续网盘化和可扩展部署

系统配置中增加 `storage.type=local|minio`，默认使用 `local`。

这样业务代码无需关心最终文件放在本地还是 MinIO，只需调用统一存储服务。

## 3. 功能设计

### 3.1 教学资源管理

当前问题：资源管理页只有 `fileUrl` 和 `coverUrl` 文本输入框，没有真实上传入口。

改造后：

1. 资源主文件上传
   - 前端使用 `FileUpload`
   - 上传成功后自动回填：
     - 文件访问地址
     - 原始文件名
     - 文件大小
     - 存储类型
     - 存储路径

2. 资源封面上传
   - 前端使用 `ImageUpload`
   - 自动回填封面地址

3. 下载与预览
   - 后端统一返回下载地址/预览地址
   - PDF、图片、文本类资源尽量支持浏览器预览
   - Office 文件先保留下载，后续可扩展在线预览

4. 资源数据模型补齐建议
   - resource_title
   - resource_type
   - file_name
   - original_file_name
   - file_ext
   - file_url
   - storage_type
   - storage_path
   - file_size_mb
   - cover_url
   - preview_url

### 3.2 课程管理 / 章节附件

当前问题：课程管理页面只是课程基础信息，缺少教学附件闭环。

改造后：

1. 课程章节增加附件上传入口
2. 每个章节可以挂多个资料文件
3. 章节附件支持：
   - 上传
   - 下载
   - 删除
   - 排序
   - 备注说明
4. 章节附件可选关联已有资源，避免重复上传

建议新增独立表存课程附件，而不是把所有课件都塞进课程主表。

### 3.3 空间文件库

当前问题：空间分享页面更像“手工填分享记录”，没有真实文件库。

改造后：

1. 文件夹管理
   - 新建文件夹
   - 重命名
   - 删除
   - 层级目录

2. 文件管理
   - 上传文件
   - 批量上传
   - 删除
   - 移动
   - 重命名
   - 查看详情

3. 分享能力
   - 公开链接分享
   - 密码分享
   - 指定授权分享（预留）
   - 分享有效期
   - 下载次数限制
   - 分享开关

4. 分享访问统计
   - 浏览次数
   - 下载次数
   - 创建时间
   - 到期时间
   - 分享人

### 3.4 配额与权限控制

当前配额页已有基础字段，但需要和真实上传行为联动。

后续规则：

1. 账号总空间限制
2. 单文件上传大小限制
3. 是否允许分享
4. 是否允许密码分享
5. 最大分享天数
6. 账号封禁后：
   - 禁止上传
   - 禁止新建分享
   - 已有分享可按策略失效

### 3.5 存储策略

#### 默认策略
- 开发环境：本地磁盘
- 生产环境：先支持本地，也可切 MinIO

#### 本地目录建议
- uploads/resource/
- uploads/course/
- uploads/space/
- uploads/image/

#### MinIO 目录建议
- teaching/resource/
- teaching/course/
- teaching/space/
- teaching/image/

## 11. 结论

本方案选择 B 路线，原因如下：

1. 能在当前项目基础上最快做成“真实可用”的教学资源系统
2. 不会陷入一次性大重构风险
3. 文件上传、课程资料、空间分享三条核心链路都能补齐
4. 本地存储和 MinIO 可同时兼容，利于后续扩展
5. 便于配套输出完整开发文档和部署文档
